Base64 Encoder & Decoder

Encode and decode Base64 in your browser, with proper UTF-8 handling so accented characters, emoji and non-Latin scripts survive the round trip.

Base64 is an encoding, not encryption

The single most important thing to know. Base64 is trivially reversible by anyone — it provides no confidentiality whatsoever. Its only purpose is to represent binary data using a set of 64 characters that survive transport through systems designed for text. If you need secrecy, use encryption; if you need integrity, use a signature or hash.

Why it exists

Many transport layers — email (historically), JSON, XML, URL query strings, HTTP headers — were built for text and mishandle arbitrary bytes. Base64 maps every 3 bytes of input onto 4 printable characters, expanding size by about 33% in exchange for safety across those channels.

The UTF-8 trap

Naive browser functions like btoa() fail on characters outside the Latin-1 range — "café", "你好", or any emoji will throw an error. Correct handling means encoding the string to UTF-8 bytes first, then Base64-encoding those bytes. This tool does both steps, so non-ASCII text round-trips correctly.

Padding and variants

Base64 output is padded with = characters so its length is a multiple of 4. There are also variants: URL-safe Base64 replaces + and / with - and _ so the output can appear in URLs and filenames without escaping. If your output will be used in a URL, use the URL-safe alphabet.

Common uses

  • Embedding small images inline in HTML or CSS as data URIs.
  • Carrying binary payloads inside JSON APIs.
  • Basic authentication headers in HTTP.
  • Storing keys or certificates in text configuration files.
