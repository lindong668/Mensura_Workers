URL Encoder & Decoder

Percent-encode text for safe use in URLs, or decode percent-encoded strings back to readable text. Handles the plus-sign-versus-%20 distinction that breaks many query strings.

Encode values, not whole URLs

The most common mistake. encodeURIComponent is for a value you are putting into a URL. Applying it to an entire URL escapes the :// and slashes too, producing something that no longer works. Encode each parameter value individually, then assemble the URL.

What must be encoded

URLs may only contain a limited character set. Reserved characters have structural meaning — ? starts a query, & separates parameters, # starts a fragment, / separates path segments. If a value genuinely contains one of these, it must be percent-encoded, or it will be interpreted as structure rather than data.

CharacterEncodedWhy
space%20Not allowed in URLs
&%26Would split parameters
=%3DWould split key from value
?%3FWould start a query string
#%23Would start a fragment
/%2FWould split path segments

"+" versus "%20"

In application/x-www-form-urlencoded bodies (HTML form posts), a space becomes +. In a URL path or query string, a space should be %20. They are not interchangeable: decoding a query string that treats + as a literal plus, or a form body that does not, produces corrupted values. This decoder treats + as a space, matching form convention.

Non-ASCII characters

URLs are defined in ASCII. International characters are converted to UTF-8 bytes, and each byte is percent-encoded — so "é" becomes %C3%A9, two bytes. Modern browsers display the readable form while transmitting the encoded form underneath.
